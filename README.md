### 新图片按透明度选择 JPG / PNG

新写入的 PNG 逐像素检查透明度：全部不透明时编码为 `.jpg`（质量 95），有任意半透明/透明像素则保留 PNG。普通切图、九宫最小化输出、平铺输出和生成渐变走同一写入规则；下载缓存仍保留原始图片。JPG 是有损格式，不保证与原 PNG 逐像素相同，也不等于降低运行时纹理内存。

同名资源查找支持 `.png`、`.jpg`、`.jpeg`（不区分大小写）。项目内命中的 JPG/JPEG 直接引用原 SpriteFrame UUID，不重新编码或复制；仍使用 Figma 原始节点名匹配，不受插件内重命名影响。原名明确带 JPG/JPEG 后缀时优先匹配该格式，否则依次匹配 PNG、JPG、JPEG。已有 PNG 不自动迁移格式，不批量修改现有资源或 Prefab。

超过 1600 万像素、无法解码或 JPG 编码失败时保留 PNG 并给出控制台警告。普通 IMAGE 原图路径会按目标 FILL/FIT 裁切生成 PNG，再按透明度选择最终 PNG/JPG；下载缓存保留 WebP/GIF/BMP 等原始内容，无法安全处理时明确报错。更新插件并重启 Creator 后，新导入生效。

### 本地同名资源与 Figma 切片的优先顺序

Figma 存在有效三/九宫定义时，先按 Figma 的模式与原边距生成到选定输出目录，输出范围外素材的图片和 Meta 保持原样。输出目录允许同时用于本地搜索，也允许位于搜索目录内。同一界面内同名只生成一份；组内有有效切片时，优先选首个有效切片作为来源，多个定义冲突时会说明选择原因，不生成内容变体。

没有有效 Figma 切片时，指定本地同名目录仍按原顺序优先，直接引用已有可用 SpriteFrame 的 UUID 和边距；其次在未强制刷新时复用输出目录同名资源。原本请求切片但无有效 Figma 边界的节点也保留这条规则；本地资源无边距时提示按普通 Sprite 显示，资源尚未入库则提示错误。匹配使用 Figma 原始名，不使用插件改名。

### Tiled 按实际平铺单元尺寸生成资源（1.0.54 · V2）

原生 Tiled 路径将 Figma 填充倍率应用到图片像素：例如 26×28 源图、50% 平铺、导入倍率 1，生成 13×14 PNG，Sprite 节点 Scale=1，背景 Content Size 仍为 Figma 目标尺寸。全局导入倍率仍参与资源尺寸计算；PATTERN 已按倍率导出的图片不重复缩放。像素尺寸四舍五入且最小为 1，不足整数时提供提示。

新资源使用独立带版本的标识，避免复用旧的原始像素资源；下载缓存继续保存原始图片，不累计缩小、不覆盖或自动删除旧文件。矩形不再因为平铺倍率创建缩放辅助节点；椭圆仍保留形状遮罩，辅助 Sprite 的 Scale 同样为 1。普通图片、三/九宫、原生平铺识别条件及 Cocos 容量设置不变。

缩小资源属于重采样（透明度加权、保留 PNG 色彩元数据），不宣称与原图 GPU 缩放逐像素完全一致。此项改动不会减少相同纹理密度下的平铺格数，不能单独解决 StaticVBAccessor 容量超限。保存项目并完整重启 Creator 后重新导入生效；不直接改写现有 Prefab。

“资源对比”点击列表项时仅更新选中高亮与右侧详情，不再重建整个页签。左侧滚动位置、保留/待删除勾选和键盘焦点保持不变；重复点击已选资源不再重新请求预览，切换后旧的异步预览结果不会覆盖新详情。搜索、筛选与翻页仍按原流程刷新列表。

### 资源定位使用单选（1.0.49 · V2）

“在资源面板中定位”改为先清空资源选择，再选中本次资源。连续定位不同图片或重复点击同一张图，不再累积多选；不清除场景节点选择，不改变报告中的保留/待删除勾选状态。

### 导入对比的 Mask 警告修复（1.0.48 · V2）

组件快照改为按类型采集颜色，不再读取会触发 Cocos 警告的旧 `Mask.color` 或已弃用的 `Mask.spriteFrame`。Mask 单独记录类型、反向、Alpha 阈值、分段数，并从实际 Sprite 渲染组件记录贴图引用；Sprite/Label/RichText/Graphics 的颜色仍参与对比，每个颜色属性只读取一次，Graphics 额外记录填充与描边颜色。自定义非渲染组件的 `color` 不再被盲目读取。

此修复只影响报告数据读取，不修改遮罩、渲染组件、坐标或三/九宫资源。更新后重新加载扩展并重新导入生成报告；旧控制台警告不会自动消失。Tiled 容量超限与“导入编辑目标已切换”是独立问题，不在此次修复范围内。

### 三/九宫图片最小化（1.0.61）

从 Figma 有效三/九宫几何读取模式和边距，保留固定边角，把中心带保留为约 2 个 Figma 逻辑像素（2 倍导出为 4 个物理像素）。节点坐标、显示尺寸和 `SLICED + CUSTOM` 模式不变。

- Figma 指定的拉伸方向与原始边距最高优先，不因像素差异取消中心缩小，不为边缘过渡自动移动分界。三宫只缩定义的方向，九宫可缩两个方向。
- 保留 PNG 色彩描述；旋转/翻转、画布不匹配、特殊 PNG 或超过 1600 万级像素的图片跳过最小化。中心原本只有 1–2 个逻辑像素时不再扩大。
- Cocos 未能确认小图的四边切片值或关闭自动裁剪时，恢复完整 PNG 后再继续原有九宫/普通图片降级流程。
- 下载缓存仍保存完整原图；有效 Figma 切片重新生成输出图片，避免把旧小图再当完整画布裁切。输出范围外素材不被改写；普通 PNG、Tiled 和原图直引不参与最小化。
- 控制台“**三/九宫资源最小化**”记录处理前后尺寸、文件字节数以及跳过/恢复原因。这里主要减少纹理像素占用，不保证每张 PNG 的磁盘文件都按相同比例变小。

更新后完整重启 Creator，再重新导入目标 Prefab。有效 Figma 切片会重新应用原定义；普通资源仍遵循刷新设置。正常使用完整下载缓存即可，不必清空缓存。固定边角较大的资源仍可能较大。

### 导入完成后的资源检查（1.0.46 · V2）

导入成功后会打开“导入结果检查”，也可从面板底部的“导入检查”重新打开本次会话最近一份报告。MCP 发起的导入同样生成报告，面板已打开时自动展示。

- **资源对比**：区分本次新建、覆盖已有、引用已有，列出实际资源路径、来源和全部引用节点。可按状态/名称筛选，对比实际图片与所选 Figma 来源图；覆盖已有图片时额外展示覆盖前缩略图。Figma 预览按需加载，避免阻塞导入。
- **确认后清理**：新建资源默认全部保留。取消勾选仅标记“待删除”；点击“确定修改”才解除受管 Sprite 的引用、保存当前目标、删除资源，节点、组件和尺寸保留。关闭弹窗或“暂不修改”会放弃勾选。已有资源不允许通过此入口删除。
- **节点对比**：按稳定节点身份对齐导入前后树，新增为绿色、删除为红色、修改为橙色；可仅看变化，展开查看组件和主要属性。另有 Figma 原树到 Cocos 合并/映射结果的对照。
- **删除校验与备份**：确认时核实文件/Meta 未被替换、编辑目标和节点树未变，检查场景内其他组件与项目资源的引用。清理前把图片、Meta、目标文件及恢复清单备份到项目 `temp/figma-importer/review-backups/<检查编号>`。保存失败会恢复引用；文件删除失败会保留文件并在报告中说明。

报告只覆盖当前插件会话最近一次成功导入；未保存的新场景需先保存再重新导入，才能启用资源删除。备份位于项目临时目录，清理该目录会移除备份。超大图片或超出缩略图预算时可能没有覆盖前预览；Figma 当前预览不代表历史版本，隐藏祖先也可能让复杂图层的 Figma 预览透明。节点组件区域展示导入相关主要属性，不是任意用户脚本的完整属性差异。

面向 Cocos Creator 3.8.7 的 Figma UI 导入扩展。它可以把 Figma 文件或单个节点转换为可编辑的 Cocos UI 节点树，也可以按节点选择 PNG 整层、九宫格或增量更新。

完整架构、数据流、安全约束、故障记录和后续变更规则见 [插件技术知识库](./FIGMA_IMPORTER_KNOWLEDGE_BASE.md)。

## 安装

1. 下载或克隆整个仓库目录。
2. 将目录直接放到 Cocos 项目的 `extensions/figma-importer-cocos`。
3. 完整重启 Cocos Creator，或在“扩展 → 扩展管理器”中刷新并启用扩展。
4. 从“面板 → Figma Importer”打开面板。

仓库已包含与当前源码和版本一致的 `dist` 构建产物，使用者不需要安装 Node.js、执行 `npm install` 或手动编译。只有参与插件开发时才需要安装依赖并运行构建命令。

如果要让 AI 客户端直接读取 Figma 链接、调整节点策略/节点名并触发导入，还需把仓库内已构建的 `mcp-dist/server.js` 配置为本地 MCP Server。详细连接方法见 [MCP 使用与连接说明](./MCP.md)。

## 使用

1. 在 Figma 创建 Personal Access Token。
2. 在“安全连接”中保存并验证 Token。
3. 添加 Section / Frame 链接到界面列表；Frame 可继续追加，Section 会展开外层界面。文件和其他节点链接仍可单独读取。
4. 勾选需要导入的界面，进入“调整节点”，用顶部标签切换 Frame，检查各自策略与预览。
5. 确认整批导入设置和目标清单；导入不会读取当前场景选中节点。
6. 开始导入并逐项检查；可停止后续、重试失败项或继续未完成项。

带 `node-id` 的 Figma Frame 链接按独立预制体导入：最外层 Frame 作为根节点，名称作为 `.prefab` 文件名，根节点挂载对应尺寸的 `UITransform`，放置在 Canvas 参考边界中心。参考画布为 640×1136，Prefab 保存到所选 `assets` 子目录。插件先创建或定位来源绑定的 Prefab，打开并验证后才写入节点，不在原场景创建临时导入根；批量时每项保存、身份检查完成后才处理下一项。

普通文件导入始终从当前场景的 Canvas 根节点开始，不会读取或修改当前选中的场景节点、预制体节点；Frame 链接则直接创建独立预制体。若要把导入结果作为子节点使用，请在预制体打开后从资源管理器拖入目标场景。

## AI / MCP 导入

MCP 服务提供单向 Figma → Cocos 自动化：读取文件或 Frame 链接、分页查询节点、获取预览、修改有限的导入设置、批量调整节点策略、批量修改 Cocos 节点名、确认后导入以及取消导入。它不会开放 Token、任意文件夹选择、动态 Creator 消息或 Round-trip 接口。

MCP 不调用或控制浏览器。读取 Figma 时由 Cocos 插件使用已保存的 Token 直接请求固定 Figma REST API；新环境只需允许访问 `api.figma.com` 的 HTTPS 网络，不需要浏览器权限。

Cocos Creator 必须已经打开目标项目并启用本扩展，但 Figma Importer 面板无需常开。首次配置 Figma Token 时仍需打开一次面板保存并验证；MCP 只使用插件主进程中已有的安全 Token，不读取其他 Figma MCP 的凭据。

已有 Figma MCP 可以帮助 AI 定位或理解设计稿，但它与本导入 MCP 是两个独立连接。把对应 Frame 链接交给 AI 后，AI 仍会通过本导入 MCP 执行“读取 → 查询/改名 → 确认导入”。完整配置、安全规则以及每个工具的输入/输出和用途见 [MCP 工具列表与连接说明](./MCP.md#mcp-工具列表与用途)。

资源输出目录用于存放最终导入 Cocos 的图片，可在面板中选择项目 `assets` 下的子目录，不再追加文件级子目录。新 PNG 不透明时转 JPG，有透明度则保留 PNG。资源直接使用 Figma 节点名，只替换文件系统不允许的字符；同名节点复用首次导入的资源，不再生成哈希或倍率后缀。

“本地同名资源目录”是可选素材来源，最多 3 个。有效 Figma 三/九宫优先生成到输出目录；其他节点按目录顺序递归匹配原始节点同名 PNG / JPG / JPEG，项目内直接绑定原 SpriteFrame 和边距，外部素材才复制导入，全部未命中才从 Figma 下载。每个目录可以单独清空，下载缓存自动维护。

## 节点策略

- 生成：转换为 `UITransform`、`Graphics`、`Label`、`Layout`、`Button`、`ScrollView`、`Mask` 等可编辑组件。
- PNG 整层：由 Figma 把当前节点及其子树渲染为一张 PNG，再导入 `SpriteFrame`；该节点的设计子层不会重复生成。
- 矢量节点：面板显示为“PNG Sprite”，通过 Figma PNG 渲染后导入 `Sprite`，不会用 `cc.Graphics` 近似任意矢量路径；它只渲染当前矢量节点，不会压平父节点子树。
- 更新：只更新已映射节点的几何与可见性。
- 九宫格：对可安全缩小的三宫/九宫 PNG 进行中心带最小化，并导入为 `Sprite.Type.SLICED`，切片边界写入 SpriteFrame 元数据；边界计算或 Cocos 元数据回读失败时使用完整 PNG 降级，不把缩小后的九宫图直接当普通图片拉伸。
- 忽略：不创建当前节点及其整棵子树。

文字节点始终按 Cocos `Label` 导入，不会因为渐变、阴影或复杂填充而导出 PNG 切图。字号严格匹配 Figma 面板显示值，不乘导入倍率，并按 Figma 面板精度最多保留两位小数：内部值 `17.8873233795166` 显示为 `17.89` 时写入 Cocos `17.89`，Figma `18` 和 `24.5` 仍分别对应 Cocos `18` 和 `24.5`。字体描边直接写入 `Label.enableOutline`、`Label.outlineColor` 和 `Label.outlineWidth`，不再添加额外的 `LabelOutline` 组件。所有文字使用 `Label.Overflow.NONE`：无显式换行符的单行文字按 Figma 参考框水平、竖直居中；包含显式换行符的多行文字按参考框左上对齐。插件先加载映射字体，再让 Cocos 完成最终字体度量和位置补偿。Cocos 3.8.7 在 `NONE` 下会强制关闭自动换行，因此 Figma 自动折行但没有手动换行符的文本会在面板显示警告。启用本地同名资源目录时，如果一个容器节点自身命中同名 PNG 资源，会把该资源作为整层 Sprite 使用，并跳过其内部子节点导入。

节点类型使用 Cocos 组件语义：`Node`、`Sprite`、`Label`、`Button`、`ScrollView`、`Layout`。滚动节点使用 `ScrollView → view（Mask）→ content（Layout）` 标准结构。

所有导入节点以及 ScrollView 自动生成的 `view/content` 都在建树时直接使用 Cocos 默认中心锚点 `(0.5, 0.5)`。插件会依据父节点实际锚点、尺寸和原始 Figma 左上坐标计算中心位置，不经过导入后的二次调整；当滚动内容大于视口时，会先确定 content 最终尺寸并补偿位置，使它的左上边界始终与 view 对齐。

“PNG 整层”是子树压平动作，旧版“合并子树”配置会自动兼容为“PNG 整层”。非根节点的 `icon_` / `img_` 默认按最外层资源边界整层合并，不要求内部有杂乱命名；自身九宫优先，内部独立九宫或子层手动策略冲突时保留结构并提示。其余容器保留既有结构与杂乱子树启发规则，明确的 ScrollView 不因杂乱子层被误压平。用户显式策略仍优先。

Figma 中手动配置了非空 Export 设置的非文字节点，会被视为设计者明确指定的资源边界：智能模式默认选择“PNG 整层”并抑制其设计子树。该显式规则同样作用于最外层节点、Figma 明确设置的 ScrollView 和隐藏节点；隐藏节点正常导入资源和结构，但在 Cocos 中初始为 Inactive。对于无描边、无特效、无圆角的纯 IMAGE 填充隐藏节点（以及与其等大的单层包装），插件会直接下载 Figma 原图，绕开 Figma 对隐藏祖先导出透明 PNG 的限制。文字节点仍保持可编辑 `Label`，空 Export 数组不触发。Export 中的 JPG/PNG/SVG/PDF 格式、后缀及 SCALE/WIDTH/HEIGHT 约束仅用于表明“人工设置过 Export”，插件实际统一请求 PNG，并使用插件“导入倍率”（默认 `1`），不会套用 Figma Export 自带倍率。

可安全表达的 Figma Auto Layout 会映射为 Cocos `Layout`；混合绝对定位、尺寸不一致的 Wrap/Grid 会保留为 `Node` 和绝对几何，避免 Cocos Layout 重排后破坏画面。裁剪只映射为 `Mask`；智能模式只有在 Figma 明确设置滚动溢出方向时才映射为 `ScrollView`，`list_`、`scroll_` 等业务命名不会擅自改变节点层级。需要预留运行时滚动但设计稿没有设置溢出时，可在节点策略中手动选择 `ScrollView`。Figma Constraints 暂不自动映射为 `Widget`，导入后由用户在 Cocos 中手动配置。

## Round-trip 回写原 Prefab（开发分支）

Round-trip 是与“导入到场景/创建新 Prefab”完全隔离的安全路径。它只读取由配套 Cocos → Figma 插件写入的 `cocosfigmabridge` Shared Plugin Data，并对导出时 Baseline、Figma 当前状态和 Cocos 当前 Prefab 做逐字段三方合并。

使用顺序：

1. 粘贴 Figma 文件或节点链接，点击“检测 Round-trip 数据”。
2. 文件有多个 managed root 时明确选择一个，再点击“生成变更预览”。
3. 首次使用且 source/meta/identity 证据完全一致时，点击“确认配对 Surface”。该操作只建立 genesis ledger，不修改 Prefab。
4. 重新生成预览，确认目标 `db://` URL、修改/保留/冲突/不支持数量。
5. 只有没有阻断且存在 patch 时，“应用到原 Prefab”才可用；Apply 接受整个不可变计划，不支持部分勾选。

P0 只写位置 x/y、UITransform 宽高和有完整 paint/resource proof 的 SpriteFrame UUID。名称、路径、Figma node id、Cocos runtime UUID 和旧 nodeMaps 都不会用于认领原节点。历史 Figma 版本链接、多个未选择 root、结构/只读视觉漂移、双方同时修改、Layout/Widget/嵌套 Prefab、非 SIMPLE + CUSTOM Sprite、目标 Prefab 当前被编辑器加载或 Creator 非 3.8.7 都会阻断写入。

事务状态保存在项目根的 `.cocos-figma-sync/`，不在 `assets` 内，包含 baseline、ledger、lock、journal、backup 和 receipt。插件不会自动修改 `.gitignore`；团队需自行决定是否版本化 ledger/baseline，`backups/`、`locks/`、`journals/` 和 `receipts/` 通常应作为本地运行状态忽略。启动时会检查未完成 journal，并且只会清理由 exact owner bytes 证明且原进程已不存在的 stale lock。

代码级门禁已通过，隔离 Creator 3.8.7 已证明扩展启用、AssetDB UUID 查询和真实 raw write/reimport/ledger commit；Prefab 打开/实例化、复杂脚本引用与 Figma 联合证据完成前，本功能仍属于实现候选，不能标记为最终 G2。

## Token 安全

- Token 只在扩展主进程中使用，面板不会读取或回显已保存 Token。
- 支持系统加密时，扩展使用 Electron `safeStorage` 加密，仅将密文写入 Cocos 本地配置。
- Windows 使用 DPAPI；macOS 使用系统钥匙串；Linux 检测到 `basic_text` 后端时拒绝持久化。
- 系统加密不可用时，Token 仅保留在当前编辑器会话。
- Token、明文或解密结果不会写入项目目录、资源、日志或节点数据。
- 内部图片缓存只保存 PNG / SVG 字节，文件夹和文件名都使用哈希键，不包含 Token、Figma fileKey 或 nodeId 明文。

## 字体映射

读取 Figma 后，面板会列出检测到的 `fontFamily`，并递归扫描项目 `assets` 下的 `.ttf`、`.otf`、`.fnt`、`.woff` 字体资源。文件名与 Figma 字体名规范化后完全或部分匹配时会自动选中；未匹配项可直接在每一行下拉框中手动选择项目字体，不需要填写 `db://` 路径或操作系统绝对路径。未映射字体使用 Cocos 默认字体，不会阻塞导入。
